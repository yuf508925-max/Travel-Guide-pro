## TS 化排查：useChatStream.ts / App.vue

- 项目由 JS 转 TS，凡 `<script setup>` 未加 `lang="ts"` 的 .vue 文件（OceanBackground / LoginView / ChatView / MessageList / MessageInput / Live2DStage），在 TS 侧 import 时会报
  `TS7016: Could not find a declaration file for module 'xxx.vue'`。
  根因：Volar 为 JS 脚本块生成的是 .js 虚拟文件，而 `allowJs` 默认 false → 无类型声明。
  已实测验证：加 `--allowJs` 后这 3 条错误消失；与 TypeScript 版本无关（5.9.3 与 6.0.3 表现一致）。
  推荐修法：给所有 `<script setup>` 加 `lang="ts"`（而非开 allowJs，避免丢失 props 类型检查）。
- App.vue 另有一处 `TS7006`：`handleLogin = (name) => {}` 参数缺类型，改为 `(name: string)`。
- 其余同类隐患（未修）：LoginView 的 `pad = (n)`、`let timer`、useChatStream 的 `sleep = (ms)`、`sendMessage(text)`、`ref([])`。
- 注意：诊断时临时 `npm i --no-save typescript@5.9.3` 做过对照实验，恢复 6.0.3 时被沙箱 bulk-delete 拦截，
  当前 node_modules/typescript 实际为 5.9.3（package.json 仍写 ~6.0.0），遗留目录 node_modules/.typescript-YrAUYxmz，需用户手动 `npm install` 还原。

## 模型不显示的两个坑（已修，重要）

### 坑 1：遮罩数量超过库上限 → 渲染直接抛异常
- 症状：页面无小人、无占位框、控制台 `[CSM][E]not supported mask count : 49 [Details] render texture count : 1, mask count : 85`
  + `Uncaught TypeError: Cannot read properties of undefined (reading 'R')`（在 CubismShader_WebGL.setupShaderProgram）
- 原因：该模型有 **85 个裁剪遮罩**。pixi-live2d-display 创建渲染器时把遮罩纹理数量写死为 1
  （`CubismRenderer_WebGL.initialize(model)` → maskBufferCount 默认 1），单张上限 36 个遮罩（`ClippingMaskMaxCountOnDefault=36`）。
  `@jannchie/pixi-live2d-display` 最新版（1.4.0）同样写死，无解。
- 修法（Live2DStage.vue 里的 `fixClippingMaskBuffer()`）：模型加载后从
  `internalModel.renderer._clippingManager._clippingContextListForMask.length` 读真实遮罩数，
  按官方 SDK 规则 `Math.ceil(mask / 32)` 算张数，再 `renderer.initialize(coreModel, n)` + `setIsPremultipliedAlpha(true)` 重新初始化。
- 依赖升级记录：`pixi.js@7.4.3` + `pixi-live2d-display@0.5.0-beta`（0.4.0 只支持 16 个遮罩、且只兼容 pixi6，已淘汰）
  - 0.5.0-beta 的 API 变化：`Live2DModel.from(url, { ticker: PIXI.Ticker.shared })`（registerTicker 已 deprecated）

### 坑 2：`model.width / model.height` 会跟着 scale 变 → 缩放来回震荡
- 症状：小人被放得巨大，只能看到腰部；`lastLayout` 探针显示 width 从 3000 变成 360.64
- 原因：`model.width` 的基准里含当前 scale，而 `layoutModel()` 每次 ResizeObserver 触发都会重算，
  于是 scale 一轮一轮震荡（3000 → 0.12 → 360 → 1.0 → …）
- 修法：改用**不含缩放**的画布尺寸 `model.internalModel.getSize()`（= canvasinfo.CanvasWidth/CanvasHeight，本模型 3000×4500）
